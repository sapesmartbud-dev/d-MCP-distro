# SAPÉ d-MCP — distribution builds

Build scripts for the installers on each operating system. Every script builds the
PyInstaller bundle from the project's own [`sape-d-mcp.spec`](../sape-d-mcp.spec) (unchanged),
smoke-tests it with `--cli --version`, and then packages it. The version is read from
[`src/sape_d_mcp/_version.py`](../src/sape_d_mcp/_version.py).

PyInstaller does not cross-compile: build each installer **on its own operating system**.
Artifacts go to `_distro/<OS>/output/` (git-ignored), with SHA-256 checksums. The build
venv and the PyInstaller work files go to the system temp folder, not the project folder.

| OS | Command | Output |
|---|---|---|
| Windows | `powershell -ExecutionPolicy Bypass -File _distro\Windows\build_windows.ps1` | `sape-d-mcp-<ver>-windows-x64-setup.exe` (Inno Setup) |
| Linux | `bash _distro/Linux/build_linux.sh [appimage] [deb] [rpm]` | `.AppImage`, `.deb`, `.rpm` |
| macOS | `bash _distro/Mac_OS/build_macos.sh` | `sape-d-mcp-<ver>-macos-<arch>.dmg` containing `SAPE d-MCP.app` |

### Linux packages from Windows (Docker)

With Docker Desktop running, the Linux packages can be built on Windows. The wrapper runs
`build_linux.sh` unchanged inside a throwaway `ubuntu:22.04` container, so it needs no
Linux toolchain and no `sudo`:

```powershell
powershell -ExecutionPolicy Bypass -File _distro\Linux\build_linux_docker.ps1            # all three formats
powershell -ExecutionPolicy Bypass -File _distro\Linux\build_linux_docker.ps1 deb rpm    # a subset
powershell -ExecutionPolicy Bypass -File _distro\Linux\test_linux_docker.ps1             # install-and-run test
```

Because the build runs on Ubuntu 22.04 (glibc 2.35), the packages run on Ubuntu 22.04+,
Debian 12+ and Fedora 36+. Use `-Image` to build on a different base. The project must be
on a local disk: Docker cannot mount a virtual cloud-sync drive such as Google Drive's.

`test_linux_docker.ps1` installs the `.deb` on clean Ubuntu 22.04 and Debian 12 and the
`.rpm` on Fedora 40, then checks the version, Qt's library dependencies, where the databases
are created, and a headless (offscreen) GUI start. It also runs the AppImage's `--cli
--version` on Ubuntu 22.04.

## Prerequisites

- **All:** Python 3.10 or newer, with network access for `pip`.
- **Windows:** [Inno Setup 6](https://jrsoftware.org/isinfo.php) (`winget install JRSoftware.InnoSetup`).
- **Linux:** `python3-venv`, `dpkg-dev` for the `.deb`, `rpm` for the `.rpm`, `curl` to fetch
  `appimagetool`, and **unixODBC** (`unixodbc`). Without unixODBC the pyodbc MS-SQL driver
  cannot be imported at build time and is left out of the bundle. Build on the oldest
  distribution you want to support, because the bundle needs the same or a newer glibc.
- **macOS:** Xcode command-line tools (`iconutil`, `hdiutil`, `codesign`). The build's
  architecture is the Python interpreter's architecture: arm64 or x86_64.

## Where the databases go

`connections.db`, `permissions.db` and `audit.db` are created in the **current working
directory** (see `src/sape_d_mcp/db_location.py`). The installers keep that rule and only
decide the working directory for a launch from the desktop:

| OS | GUI launched from the menu / Finder | Launched from a terminal |
|---|---|---|
| Windows | `%LOCALAPPDATA%\SAPE\d-MCP` (shortcut working directory) | the terminal's directory |
| Linux `.deb`/`.rpm` | `${XDG_DATA_HOME:-~/.local/share}/sape/d-mcp` (via `sape-d-mcp-gui`) | the terminal's directory (`sape-d-mcp`) |
| Linux AppImage | the directory it was started from, or the XDG path above if that is `/` or not writable | same |
| macOS | `~/Library/Application Support/SAPE/d-MCP` if started from `/` or an unwritable directory | the terminal's directory |

MCP clients start the server with explicit `DMCP_*_DB` paths generated by the GUI, so these
defaults do not affect them. Uninstalling never deletes the data directory.

## Per-OS notes

- **Windows:** the install is per-user (`%LOCALAPPDATA%\Programs\SAPE d-MCP`), with no admin
  rights and no UAC prompt. The installer offers English and Spanish.
- **Linux:** the `.deb` and `.rpm` install to `/opt/sape-d-mcp`, with `sape-d-mcp` on `PATH`
  and a desktop entry. The `.rpm` dependency names follow Fedora/RHEL.
- **macOS:** signing and notarization are optional and are switched on with
  `MACOS_SIGN_IDENTITY` and `MACOS_NOTARY_PROFILE`. An unsigned `.dmg` works, but Gatekeeper
  blocks the first launch until the user right-clicks the app and chooses **Open**.

## Signing the Windows build

Without a certificate the build is unsigned, and SmartScreen warns on first launch. To sign
with a `.pfx`, set two environment variables in the PowerShell session before building:

```powershell
$env:SIGN_PFX_PATH = "C:\path\to\codesign.pfx"
$env:SIGN_PFX_PASSWORD = Read-Host "PFX password"   # typed, not stored in history or files
powershell -ExecutionPolicy Bypass -File _distro\Windows\build_windows.ps1
```

This signs `sape-d-mcp.exe`, the installer and the uninstaller with SHA-256 and an RFC 3161
timestamp (default `http://timestamp.digicert.com`; override with `SIGN_TIMESTAMP_URL`).
The certificate is imported into the current user's store only for the build and removed
afterwards, so the password never appears on a command line or in the build log. For a
certificate that is already in the store, such as one on a USB token, set
`SIGN_CERT_THUMBPRINT` instead. Signing needs `signtool.exe` from the Windows SDK.

A standard (OV) certificate removes the "unknown publisher" label straight away, but
SmartScreen may still warn until the certificate builds a download reputation.
